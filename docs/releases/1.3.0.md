# DLSS 5 Neural Rendering 1.3.0

## Changes

- **Smooth-mode failures are now logged**, with the same five-second throttling as Low latency mode. Unsupported feature creation no longer disappears into the Status field alone.
- **Readable NGX error names** accompany numeric creation/evaluation errors, including FeatureNotSupported, InvalidParameter, OutOfDate, OutOfGPUMemory, and Denied. FeatureNotSupported is not presented as proof that a particular GPU generation is the sole cause.
- **Failed creation retries are limited to once every five seconds** for unchanged creation settings. Changing resolution, style, preset, Temporal mode or processing path allows another attempt immediately.
- Added **Advanced → Retry Feature Now** to bypass the creation cooldown without restarting OBS.
- Added opt-in **Advanced → Diagnostic logging**. Logs record actual NGX core/runtime/shim paths, file versions and byte counts; adapter IDs and driver version; processing dimensions and creation settings; and input/output resource formats and flags. Restart OBS after enabling the option to request verbose NGX initialization logs. Creation-parameter logging can be enabled immediately; disabling stops forwarding immediately.
- Corrected the NGX logging structure to match NVIDIA's documented callback/level/disable-sinks ABI. Logging callbacks use a retained shim trampoline, and callback consumers are drained before plugin teardown.
- Release the retained DXGI adapter during bridge shutdown rather than leaving its final release to DLL teardown. Unsupported-feature tests cover this shutdown path.
- On processing failure, Smooth mode returns to live pass-through rather than holding an old enhanced result. Performance status does not overwrite the active worker failure.
- Corrected the README's GPU/runtime compatibility claims and added a troubleshooting procedure for [issue #2](https://github.com/Saganaki22/obs-dlss5-nr/issues/2).

## GPU compatibility

**This release improves diagnostics and failure handling; it does not add RTX 40-series support.** As of October 21, 2026, [NVIDIA's hardware support table](https://www.nvidia.com/en-us/geforce/technologies/dlss/) lists DLSS 5 Neural Rendering for RTX 50-series. NVIDIA describes RTX 40-series support as planned in its [DLSS 5 FAQ](https://www.nvidia.com/en-us/geforce/forums/nvidia-app/129/583738/dlss-5-faq-932026/).

The 1.2.5 README repeated community reports about 310.8 on older GPUs. Those were not verified with this plugin and an unmodified runtime. We have no confirmed unmodified runtime recommendation for RTX 40-series. The same 310.9.16 file reportedly working on an RTX 5090 and failing on an RTX 4080 Laptop is consistent with a support limitation, but the systems also use different drivers.

`0xBAD00001` is **FeatureNotSupported** in [NVIDIA's NGX definitions](https://github.com/NVIDIA/DLSS/blob/main/include/nvsdk_ngx_defs.h): current system, hardware, and/or graphics API support is insufficient. Initialization succeeding does not guarantee that feature creation will succeed.

## Validation

- Automated tests cover frame pacing/resolution behavior, result decoding, NGX structure sizes/offsets, the five-second creation cooldown, settings/manual retry bypass, and concurrent callback detach/reattach.
- Isolated OBS failure tests exercise FeatureNotSupported in both Smooth and Low latency modes with test-only NGX/NR fixtures. They check changing/nonblack pass-through, decoded status, bounded creation attempts, immediate manual/style retries, logging callbacks, and shutdown.
- Real-runtime checks use an RTX 5090, driver 617.14 and the locally installed NR runtime 310.8.0.0, with diagnostics enabled and disabled. Both diagnostics-on and diagnostics-off runs delivered 300 changing, nonblack frames in a ten-second window at 30 enhanced FPS, with zero missed render frames and clean shutdown. These do not reproduce or validate RTX 4080 Laptop compatibility or runtime 310.9.16.

## Installation and diagnostics

Download **obs-dlss5-nr-1.3.0-windows-x64.zip**, close OBS, extract into `C:\ProgramData\obs-studio\plugins\`, and restart OBS. Replace **both** the plugin and the matching project-built `nvngx.dll_obs.dll` caller shim. Older shim versions do not contain the new logging exports and will produce a clear version-pairing error.

Continue supplying your own `nvngx_dlssnr.dll` at `%APPDATA%\obs-studio\plugin_config\obs-dlss5-nr\runtime\nvngx_dlssnr.dll`. NVIDIA's runtime and the failure-test fixtures are **not included**. The only uploaded release asset is the Windows x64 ZIP; it includes the README, license and these patch notes. GPU sharing remains experimental and disabled by default.

For a diagnostic report, enable Diagnostic logging, restart OBS, reproduce the failure, and share the OBS log after reviewing local file paths. Disable diagnostics after collecting the log.
